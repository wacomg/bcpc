                    ПРОМТ ДЛЯ РАЗРАБОТКИ PYTHON-ПРОГРАММЫ
                    АВТОНАСТРОЙКИ PID ДЛЯ BC SERIES
================================================================================

КОНТЕКСТ
================================================================================

Я разрабатываю программу на Python для автонастройки PID-регуляторов (тока,
скорости и положения) для сервоприводов BC Series, управляемых по протоколу
CANopen (CiA 301). В качестве основы используется рабочий файл `mc.py`,
который реализует базовое управление двигателем через SDO и NMT команды.

Техническая документация:
1. App_note.txt — краткое описание протокола CANopen для DCH Controls
2. BCPC_doc.txt — расширенная документация по всем объектам CANopen

Текущее состояние:
Файл `mc.py` работает, но есть проблемы с размерностями параметров
(скорость в counts/s, ускорение в counts/s², позиция в counts).

ОСОБЕННОСТИ ОБОРУДОВАНИЯ
================================================================================

1. Два типа двигателей для настройки:
   - 2 кВт
   - 4 кВт

2. Два режима работы:
   - Без нагрузки (двигатель на столе, вал свободен)
   - С нагрузкой (присоединен механизм, редуктор, инерционная масса)

3. Критическая проблема:
   - При работе без нагрузки двигатель имеет минимальный момент инерции
   - Если подать резкий сигнал (большой момент или скорость), двигатель
     мгновенно набирает скорость, которая может его разрушить
   - Необходима защита от переразгона

4. Требуемые меры безопасности:
   - Ограничение максимальной скорости (программное)
   - Плавное нарастание сигнала (ramp)
   - Защита по току
   - Мониторинг скорости в реальном времени
   - Автоматическая остановка при превышении порога


ЗАДАНИЕ ДЛЯ РАЗРАБОТЧИКА
================================================================================

Разработай полную программу на Python для автонастройки PID сервопривода
BC Series с CANopen интерфейсом, учитывающую особенности работы как с
нагрузкой, так и без неё.

1. ВЫБОР МЕТОДА АВТОНАСТРОЙКИ
================================================================================

Мой выбор: Адаптивный метод релейной автоколебаний (Relay Feedback)
с контролируемым нарастанием амплитуды (Ramped Relay Feedback).

Обоснование:
- Не требует точной математической модели системы
- Работает в реальном времени с фактическим объектом
- Определяет критическую частоту и критический коэффициент усиления
- Позволяет настроить все три контура последовательно
- Может быть реализован через CANopen SDO команды без изменения прошивки
- Даёт повторяемые результаты
- ПОЗВОЛЯЕТ КОНТРОЛИРОВАТЬ АМПЛИТУДУ КОЛЕБАНИЙ (критично для работы без нагрузки)
- Позволяет постепенно увеличивать амплитуду до появления устойчивых колебаний

Модификации для работы без нагрузки:
1. Начальная амплитуда: 1-2% от номинала
2. Постепенное увеличение амплитуды (ramp) с контролем скорости
3. Ограничение максимальной скорости на уровне 30% от номинала
4. Автоматическая остановка при превышении порога скорости
5. Использование гистерезиса для защиты от шумов

3. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
================================================================================

3.1. CAN в отдельном потоке
- CAN чтение/запись в отдельном потоке с использованием python-can
- Использовать threading или asyncio
- Реализовать очереди команд для потокобезопасности
- Поддержка нескольких Node ID одновременно

3.2. Отсутствие блокировок
- Использовать неблокирующие операции
- bus.recv(timeout=0.001) с проверкой
- Асинхронная обработка ответов
- Разделение на чтение и запись в разных потоках

3.3. GUI на PyQt5 или tkinter
- Подключение к CAN (кнопка)
- Выбор Node ID (выпадающий список)
- Выбор типа нагрузки (без нагрузки / с нагрузкой)
- Выбор мощности двигателя (2 кВт / 4 кВт)
- Ручная активация двигателя (включение/выключение)
- Панель управления движением (G1 X F)
- Кнопки для автонастройки каждого контура
- Отображение текущего статуса, позиции, тока, скорости
- Графики в реальном времени (matplotlib или pyqtgraph)

3.4. Логирование (полное)
- User Log: все действия пользователя (клики, команды)
- CAN Log: все CAN сообщения (время, ID, данные)
- Data Log: позиция, ток, напряжение, скорость, ошибка, статус
- Safety Log: все срабатывания защиты, превышения скорости, тока
- Формат: CSV с временными метками
- Ротация логов по размеру


4. МОДУЛЬ БЕЗОПАСНОСТИ (SAFETY MONITOR)
================================================================================

4.1. Параметры защиты

Для работы без нагрузки:
- Максимальная скорость: 500 RPM (программное ограничение)
- Максимальное ускорение: 500 RPM/s
- Максимальный ток: 30% от номинала
- Порог аварийной остановки: 800 RPM
- Время реакции: < 50 мс

Для работы с нагрузкой:
- Максимальная скорость: 2000 RPM (программное ограничение)
- Максимальное ускорение: 2000 RPM/s
- Максимальный ток: 80% от номинала
- Порог аварийной остановки: 2500 RPM
- Время реакции: < 50 мс

4.2. Режимы нарастания сигнала (Ramp Modes)

Для автонастройки без нагрузки используется Ramped Relay Feedback:

1. Начальная амплитуда: 2% от номинала
2. Шаг увеличения амплитуды: 1% каждые 2 секунды
3. Критерий остановки увеличения: появление устойчивых колебаний
4. Максимальная амплитуда: 20% от номинала (ограничение)
5. Контроль скорости в реальном времени

Для автонастройки с нагрузкой:
1. Начальная амплитуда: 10% от номинала
2. Шаг увеличения амплитуды: 5% каждые 1 секунду
3. Критерий остановки: появление устойчивых колебаний
4. Максимальная амплитуда: 50% от номинала

4.3. Действия при срабатывании защиты

1. Немедленная остановка двигателя (Quick Stop)
2. Логирование события с полными параметрами
3. Отображение предупреждения в GUI
4. Блокировка дальнейших команд до сброса
5. Сохранение последних 100 точек данных для анализа


5. ОБЪЕКТЫ CANopen ДЛЯ АВТОНАСТРОЙКИ
================================================================================

Контур тока (Current Loop) — 0x2380:
- 0x2380-1: Current P Gain (0-32767)
- 0x2380-2: Current I Gain (0-32767)
- 0x2380-3: Current Offset (0.01 A)
- 0x221C: Actual Motor Current (0.01 A)
- 0x221D: Commanded Current (0.01 A)

Контур скорости (Velocity Loop) — 0x2381:
- 0x2381-1: Velocity P Gain (0-32767)
- 0x2381-2: Velocity I Gain (0-32767)
- 0x2381-3: Acceleration Feed Forward
- 0x6069: Actual Velocity (0.1 counts/s)
- 0x60FF: Target Velocity (0.1 counts/s)
- 0x2103: Max Velocity (ограничение максимальной скорости)

Контур положения (Position Loop) — 0x2382:
- 0x2382-1: Position P Gain (0-32767)
- 0x2382-2: Velocity Feed Forward
- 0x2382-3: Acceleration Feed Forward
- 0x6064: Position Actual (counts)
- 0x607A: Target Position (counts)

Ограничения (для защиты):
- 0x2100: Max Acceleration
- 0x2101: Max Deceleration
- 0x2103: Max Velocity

Режимы работы:
- 0x6060 = 1: Profile Position Mode
- 0x6060 = 3: Profile Velocity Mode
- 0x6060 = 4: Profile Torque Mode


6. АЛГОРИТМ АВТОНАСТРОЙКИ (С УЧЕТОМ ЗАЩИТЫ)
================================================================================

6.1. Общий алгоритм для всех контуров

1. Проверка состояния: IN1 = LOW, нет ошибок
2. Включение двигателя (0x6040 = 0x000F)
3. Установка программных ограничений (в зависимости от режима)
4. Запуск Safety Monitor в отдельном потоке
5. Выполнение автонастройки с контролируемым нарастанием амплитуды
6. Анализ полученных данных
7. Расчет PID коэффициентов
8. Запись коэффициентов в усилитель
9. Верификация (проверка отклика)
10. Отключение Safety Monitor

6.2. Автонастройка тока (Current Loop)

Без нагрузки:
1. Начальный сигнал: 2% от номинального тока
2. Увеличение на 1% каждые 2 секунды до появления колебаний
3. Мониторинг скорости: если > 500 RPM — остановка
4. Мониторинг тока: если > 30% номинала — остановка
5. Фиксация параметров колебаний (частота, амплитуда)
6. Расчет PI коэффициентов по формулам релейного метода

С нагрузкой:
1. Начальный сигнал: 10% от номинального тока
2. Увеличение на 5% каждые 1 секунду до появления колебаний
3. Мониторинг скорости: если > 2000 RPM — остановка
4. Мониторинг тока: если > 80% номинала — остановка
5. Фиксация параметров колебаний
6. Расчет PI коэффициентов

6.3. Автонастройка скорости (Velocity Loop)

Без нагрузки:
1. Начальный сигнал: 50 RPM
2. Увеличение на 25 RPM каждые 2 секунды до появления колебаний
3. Максимальная скорость: 500 RPM
4. Мониторинг тока: если > 30% номинала — остановка
5. Мониторинг ускорения: если > 500 RPM/s — остановка
6. Фиксация параметров колебаний
7. Расчет PI коэффициентов

С нагрузкой:
1. Начальный сигнал: 200 RPM
2. Увеличение на 100 RPM каждые 1 секунду до появления колебаний
3. Максимальная скорость: 2000 RPM
4. Мониторинг тока: если > 80% номинала — остановка
5. Фиксация параметров колебаний
6. Расчет PI коэффициентов

6.4. Автонастройка положения (Position Loop)

Без нагрузки:
1. Начальное перемещение: 5% от диапазона
2. Увеличение на 5% каждые 2 секунды
3. Максимальное перемещение: 30% от диапазона
4. Мониторинг скорости: если > 500 RPM — остановка
5. Мониторинг ошибки слежения
6. Расчет P или PID параметров

С нагрузкой:
1. Начальное перемещение: 10% от диапазона
2. Увеличение на 10% каждые 1 секунду
3. Максимальное перемещение: 80% от диапазона
4. Мониторинг скорости: если > 2000 RPM — остановка
5. Расчет P или PID параметров


7. РАЗМЕРНОСТИ (ВАЖНО!)
================================================================================

Позиция:
- Единица: counts
- Значение: int32
- Формула: degrees * (encoder_res * gear_ratio / 360)
- Пример: 45° = 45 * (131072 / 360) = 16384 counts

Скорость:
- Единица: 0.1 counts/s (ВНИМАНИЕ! В старой версии было counts/s)
- Из документации: Address 0x6081 = 0.1 count/s
- Пример: 1000 RPM = 1666666 counts/min = 0x195460 в 0.1 counts/s
- Пересчёт: velocity_raw = int(speed_rpm * encoder_res * 10 / 60)
- Для encoder_res = 131072: velocity_raw = int(rpm * 131072 * 10 / 60)

Ускорение:
- Единица: 10 counts/s²
- Address 0x6083 = 10 counts/s²
- Пример: 100 r/s² = 100 * 10 = 1000

Ток:
- Единица: 0.01 A
- Address 0x221C, 0x221D
- Пример: 1.5 A = 150

Напряжение:
- Единица: 0.1 V
- Address 0x2384-6

Для двигателей 2 кВт и 4 кВт:
- Номинальный ток 2 кВт: ~6.5 A (650 в 0.01A)
- Номинальный ток 4 кВт: ~12.5 A (1250 в 0.01A)
- Пиковый ток 2 кВт: ~19.5 A (1950 в 0.01A)
- Пиковый ток 4 кВт: ~37.5 A (3750 в 0.01A)


8. БЕЗОПАСНОСТЬ (ОБНОВЛЕНО)
================================================================================

8.1. Аппаратная защита
- Проверка IN1 перед включением (IN1 = LOW)
- Концевые выключатели (положительный и отрицательный)
- Датчик температуры двигателя

8.2. Программная защита
- Ограничение максимальной скорости (в зависимости от режима)
- Ограничение максимального ускорения
- Ограничение максимального тока
- Мониторинг ошибки слежения
- Мониторинг Status Word (бит 3 = Fault)
- Таймауты на все операции

8.3. Защита при автонастройке без нагрузки
- Начальная амплитуда: 2% от номинала (очень маленькая)
- Постепенное увеличение амплитуды с контролем
- Максимальная скорость: 500 RPM (жесткое ограничение)
- Автоматическая остановка при превышении 800 RPM
- Время реакции: < 50 мс
- Дублирование защиты на уровне CAN (быстрая остановка)

8.4. Защита при автонастройке с нагрузкой
- Начальная амплитуда: 10% от номинала
- Постепенное увеличение с контролем
- Максимальная скорость: 2000 RPM
- Автоматическая остановка при превышении 2500 RPM

8.5. Аварийная остановка
- По Ctrl+C
- При потере связи
- При срабатывании защиты
- При ручной команде Emergency Stop

9.2. Требования к графику положения

1. Отображение позиции двигателя в реальном времени
2. Автоматическое масштабирование (autoscale) по оси Y
3. Окно отображения: 2-5 секунд (настраивается пользователем)
4. На графике отображаются:
   - Фактическая позиция (синяя линия)
   - Целевая позиция (красная пунктирная линия) — опционально
   - Ошибка позиции (зеленая линия) — опционально
   - Скорость (оранжевая линия) — опционально
   - Ток (фиолетовая линия) — опционально
5. Подписи осей: время (сек) и позиция (counts или градусы)
6. Сетка для удобства чтения
7. Обновление графика с частотой не менее 20 Гц (50 мс)

9.3. Требования к отображению параметров автонастройки

1. Таблица с текущими параметрами настраиваемого контура
2. Отображение для каждого параметра:
   - Название параметра
   - Текущее значение (измеренное или установленное)
   - Целевой диапазон (допустимые значения)
   - Статус (OK/WARN/FAIL)
3. Дополнительные параметры для работы без нагрузки:
   - Текущая скорость (RPM)
   - Максимальная достигнутая скорость
   - Текущая амплитуда сигнала (%)
   - Количество циклов колебаний

# Пример использования программы
from motor_autotune import MotorController, AutotuneEngine, SafetyMonitor

# Создание контроллера с настройками безопасности
motor = MotorController(
    interface='can0',
    node_id=3,
    motor_power=2000,  # 2 кВт
    load_mode='no_load'  # или 'with_load'
)

# Настройка защиты
safety = SafetyMonitor(
    max_speed=500,      # RPM для no_load
    max_current=30,     # % от номинала
    max_accel=500       # RPM/s
)

# Подключение
motor.connect()

# Включение с проверкой безопасности
motor.enable(safety_check=True)

# Автонастройка тока (с адаптивной амплитудой)
autotune = AutotuneEngine(motor, safety)
params = autotune.tune_current()
print(f"Current P: {params.p}, I: {params.i}")
print(f"Амплитуда колебаний: {params.amplitude}%")
print(f"Частота: {params.frequency} Гц")

# Движение с ограничениями
motor.move_to_position(45.0, 10.0, safety_override=False)

# Выключение
motor.disable()
motor.disconnect()
